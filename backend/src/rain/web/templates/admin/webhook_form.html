A "Generic" webhook posts a JSON payload template you write; the payload template is ignored for GET (no body). Placeholders available depend on the caller: a Platform Response Rule's "Call a webhook"/"Notify Slack"/"Notify Email" action, and the ticket detail page's "Escalate" button, all fill in {{ticket_number}}, {{ticket_type}}, {{title}}, {{description}}, {{severity}}, and {{status}} from the ticket that triggered the call - double braces, JSON-escaped automatically. A document's "Refresh from webhook" (and the calendar's matching auto-update policy) calls with no placeholders at all, so a payload template used there should be static. A "Chat Completions API" webhook is different: instead of a payload template, it calls an OpenAI-compatible endpoint (OpenAI itself, Gemini's own compatibility endpoint, or anything else speaking the same {model, messages} shape) with a system message built from your own prompt and/or a linked document's text, and a user message built from whichever ticket a Platform Response Rule's "Invoke Chat Completions API" action ran it against - the reply comes back as a new comment on that ticket.{% endraw %}{% endblock %} {% block content %}
